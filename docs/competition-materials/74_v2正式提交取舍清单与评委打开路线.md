## 1. 提交策略

当前材料包历史版本很多，正式提交时不建议把所有文件一股脑交上去。评委最需要看到的是：题目要求是否覆盖、Demo 是否可运行、闭环是否真实、创新是否讲清、边界是否可信。

正式提交建议采用“四件主材料 + 两类备查材料”：

1. **项目计划书**：用 v2 真实闭环版设计方案。
2. **可运行 Demo / 源代码**：用 `sepath-yudao-teacher-console` 作为主工程。
3. **演示视频**：用 4 分 40 秒视频素材或按 v2 脚本重录 3-5 分钟版本。
4. **答辩 PPT**：用 v0.3 真实闭环版 PPT。
5. **创新与答辩备查**：用 73 号材料。
6. **证据账本与验收备查**：用 Demo 导出的 JSON、QA 记录和流程测试结果。

**一句话原则：**主包要少而硬，备查要能证明“不是静态页面、不是聊天壳、不是高风险自动评价”。

## 4. 评委 3 分钟打开路线

### 第 1 分钟：看清题目对齐

打开 PPT 第 1-4 页或设计方案摘要，评委应立即看到：

- 场景：软件工程项目式学习。
- 问题：PR/CI/Review/反思等过程证据没有变成学习路径。
- 方案：证据驱动学习闭环工作台。
- 边界：AI 只给候选脚手架，教师确认后发布。

### 第 2 分钟：看清 Demo 能动

打开本地 Demo 或演示视频，评委应看到：

- 课程工单队列进入学生增值诊断单。
- 当前能力、期望能力、差值、不确定性和证据覆盖展示。
- Safe-VOI 给出低风险下一步。
- 教师选择批准、退回补证据或转人工会谈。
- 学生补证据和反思后，闭环阶段更新。

### 第 3 分钟：看清创新不是壳

打开 73 号材料或证据账本，评委应看到：

- EvidenceEvent 证据模型。
- ValueAddedDimension 增值评价。
- Safe-VOI 策略。
- TeacherDecision 教师发布门。
- JSON 证据账本可导出。
- 芋道/Element Plus 管理台落地路径。

## 5. 提交前口径

### 一句话简介

SE-Path 学伴是面向软件工程项目式学习的证据驱动学习闭环工作台，把 PR、CI、Review、对话、教师复核和学生反思统一成证据账本，再用增值评价与 Safe-VOI 选择下一步脚手架行动，最终由教师确认发布。

### 平台简介短版

本作品面向软件工程课程中的项目式学习场景，构建一个可运行的自适应学习伙伴智能体。系统从 PR、CI、测试、Review、学生对话和反思中采集证据，形成学生能力画像和增值诊断单；当学生遇到困难时，智能体不会直接给答案，而是根据 Safe-VOI 策略提供低风险、高价值、可复核的脚手架行动。教师在芋道风格工作台中完成复核、补证据或人工会谈决策，学生完成修复与反思后，系统写入证据账本并更新学习路径。

### 边界声明

当前 v2 Demo 使用本地 mock API 和本地状态证明闭环，不宣称已接入真实学校生产数据。增值评价只做形成性诊断和学习支持，不做排名、不做惩罚、不做就业预测。AI 只生成候选建议，发布、评价和高风险判断均需要教师确认。证据不足时，系统显示不确定或待补证，不强行给结论。

# 算法与科研思想融合说明

SE-Path 学伴不是重新包装一个聊天机器人，而是把此前路径增值引擎的研究思想迁移到“软件工程项目式学习”场景中，形成可运行产品闭环。

## 思想来源与迁移

| 原有思想/模块 | 原含义 | 在 SE-Path 中的产品化表达 |
| --- | --- | --- |
| 路径数字孪生 | 学生成长路径不是单线推荐，而是多路径、多状态、可切换、可回滚的动态模型 | `src/engine/pathTwin.ts` 根据证据实时更新需求、实现、测试、协作、反思等能力节点状态 |
| SafeVOI | 在收益、信息增益、迁移性、窗口期、负担和风险之间做安全下一步选择 | `src/engine/safeVoi.ts` 对检查清单、mini lab、教师复核、付费导师等行动排序并拦截不安全行动 |
| 安全发布门 | 低证据、低置信度、高风险、越权或高影响建议不得直接发布 | `src/engine/reviewGate.ts` 将高风险建议转入教师复核或延迟发布 |
| 证据账本 | 每次判断必须保留来源、置信度、时间和可审计证据 | `src/data/seed.ts` 与 `src/engine/evidence.ts` 把 baseline、Git、CI、chat、reflection 统一为 EvidenceEvent |
| 增值评价 | 比较学生相对自身基线的阶段性成长，不做惩罚性排名 | `scoreCompetencies` 在基线画像上累加工程学习证据，展示路径状态变化 |
| 红队边界 | 不能把 AI 建议当成真实效果证明，不能替代教师和伦理审查 | 应用明确拒绝直接替写完整代码，高风险动作进入教师复核台 |

## 为什么适合软件工程学习

软件工程课程天然留下过程证据：Issue、Commit、PR、CI、测试日志、Review 讨论、反思文档。这些证据比一次测验更适合判断学生是否真正掌握工程能力。

SE-Path 的创新点是把这些工程证据接入自适应学习路径：

1. CI 失败不是单纯扣分，而是诊断测试能力和需求边界的证据。
2. PR 描述不是形式材料，而是协作交付和反思迁移的证据。
3. AI 对话不是直接答疑，而是触发脚手架、拒答和教师复核的状态事件。
4. 教师复核不是额外负担，而是高风险建议的发布门和课堂干预入口。

## 当前代码对应

| 文件 | 作用 |
| --- | --- |
| `src/domain/types.ts` | 统一定义学习证据、诊断卡、路径节点、策略决策、教师工单等领域对象 |
| `src/engine/evidence.ts` | 证据聚合、能力分数更新、证据覆盖度计算 |
| `src/engine/diagnosis.ts` | 基于证据的学情诊断与阻塞定位 |
| `src/engine/safeVoi.ts` | 安全下一步行动排序与不安全行动拦截 |
| `src/engine/scaffold.ts` | 分级脚手架提示与直接答案拒绝 |
| `src/engine/reviewGate.ts` | 教师复核、安全发布门和高风险建议治理 |
| `src/engine/pathTwin.ts` | 路径数字孪生状态计算 |
| `src/engine/traces.ts` | 生成式 AI 可观测追踪的前端模拟 |
| `src/engine/engine.test.ts` | 闭环核心行为的单元测试 |

## 后续增强路线

1. 将 `src/engine` 迁移为后端策略服务，保留前端作为工作台。
2. 接入真实 GitHub Classroom/GitLab 课程仓库事件。
3. 用课程 Rubric 和教材资料构建软件工程知识图谱。
4. 用 RAG 评测集验证检索引用、脚手架粒度和拒答准确性。
5. 用影子运行和等待组试点验证安全性、教师负担和学习行为变化。
